# WEBWB backend — API хранения проектов (шаг 06)

Небольшой C++17 HTTP-сервер на Boost.Beast (только заголовочные файлы), `json-c` и CMake. Проверяет и сохраняет JSON-проекты версии 3; пока не хранит шаблоны/изображения и не работает с MQTT.

## Зависимости для сборки в WSL

- CMake >= 3.16;
- компилятор C++17 (`g++` или совместимый);
- заголовки Boost.Beast/Asio (`libboost-dev`);
- библиотека `json-c` и заголовки (`libjson-c-dev`) для проверки проекта;
- pthreads (на Linux обычно входит в систему).

Установка зависимости при её отсутствии в Debian/Ubuntu WSL:

```bash
sudo apt update
sudo apt install -y cmake g++ libboost-dev libjson-c-dev
```

Зависимости не скачиваются сборщиком CMake. Boost используется только через заголовки, без динамических библиотек Boost. `json-c` линкуется как системная библиотека. Перед кросс-компиляцией под WB нужно проверить архитектуру процессора и доступность этих заголовков в toolchain/среде сборки.

## Сборка и проверка в WSL

Из корня репозитория выполните **одну команду**:

```bash
bash tests/check.sh
```

Скрипт выполняет CMake-сборку в `/tmp/webwb-build`, 4 CTest и проверку HTTP API (`tests/smoke_api.py`). Сборка вынесена в `/tmp`, чтобы в репозитории не появились артефакты CMake.

## Автоматическая проверка API — одна команда в WSL

Если нужно повторно проверить только HTTP API после сборки:

```bash
python3 tests/smoke_api.py
```

Тестовый скрипт **сам** запускает backend на свободном локальном порту, создаёт временный каталог хранения, проверяет `/api/health`, валидацию, создание/список/чтение/изменение/удаление проекта и сохранность после перезапуска backend. Затем останавливает backend и удаляет тестовые файлы. Запущенные пользователем процессы и реальные проекты не затрагивает. Дополнительные Python-библиотеки не нужны.

Если бинарник собран в другом каталоге, передайте путь:

```bash
python3 tests/smoke_api.py /путь/к/webwb_backend
```

Для обычного ручного запуска backend (необязательно для проверки):

```bash
/tmp/webwb-build/webwb_backend --port 8088 --data-dir /tmp/webwb-data
```

Полное описание HTTP-маршрутов: [API](../docs/API.md).

Формат и его ограничения описаны в [docs/PROJECT_FORMAT.md](../docs/PROJECT_FORMAT.md). `ctest` дополнительно проверяет ограничения вложенности, число узлов, типы полей и некорректные документы.

Слушает **только** `127.0.0.1`; отдельная авторизация приложения не предусмотрена. Каталог `<data-dir>/projects` создаётся при запуске и содержит `<id>.json`. Изменение проекта записывается через временный файл и переименование. Путь для контроллера по умолчанию: `/mnt/data/webwb`.

Ограничения текущего этапа: синхронная обработка одного соединения за раз (ограничение чтения 5 секунд), без TLS, nginx, установки в systemd. Проекты сохраняются, но библиотека шаблонов и загрузка изображений ещё не реализованы. Сборка под WB будет проверена отдельно.
