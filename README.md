# WEBWB

WEBWB — лёгкий визуальный редактор панелей управления для контроллеров Wiren Board.

Пользователь собирает интерфейс из контейнеров, текста, кнопок, переключателей и ползунков, настраивает внешний вид и привязывает состояния к MQTT-топикам. Правила и автоматизация остаются на самом контроллере.

## Текущее состояние

**Шаги 01–11 подтверждены** (последний SHA: `404bd2db7e4f6fbad97f9ecaceca7883cb244f70`). **Шаг 12 подготовлен:** отправка MQTT-команд из кнопок, переключателей и ползунков в отдельном просмотре.

Редактор поддерживает контейнеры, текст, кнопки, переключатели, ползунки и существующий компонент изображения, Drag & Drop, дерево, CSS-свойства, проекты и шаблоны на backend. Добавление из палитры — **только перетаскиванием**. Для изображения используется существующая загрузка PNG/JPEG/WebP до 1 МиБ; backend сохраняет файлы отдельно от JSON.

**Отложено по просьбе владельца:** вместо отдельного элемента изображения использовать изображение как фон обычного контейнера. На шаге 11 изображения не меняем.

Общие настройки доступны через `GET/PUT /api/settings`; отдельную панель настроек пока не добавляем.

## Запуск и тесты — WSL

Нужны CMake, компилятор C++17, `libboost-dev`, `libjson-c-dev` и Python 3 (тесты и dev-сервер). Для обязательной проверки MQTT-команд нужен Node.js; без него `tests/check.sh` сообщает о пропуске этой части проверки.

**Все автоматические тесты одной командой:**

```bash
cd /mnt/c/Projects/WEBWB
bash tests/check.sh
```

**Запуск редактора вместе с backend:**

```bash
cd /mnt/c/Projects/WEBWB
bash tests/run_editor.sh
```

Откройте в Windows **http://localhost:8090/**. Сохраните проект, затем нажмите «Открыть панель», чтобы открыть отдельный viewer по адресу `http://localhost:8090/viewer.html?id=ID_ПРОЕКТА` (вместо ID указывается идентификатор проекта). Несохранённые изменения в viewer не видны. Элементы без MQTT-привязок работают демонстрационно; привязанные элементы читают MQTT-статусы и могут отправлять команды при действии пользователя, если задан `actionTopic`. Адрес подключения описан в [docs/VIEWER.md](docs/VIEWER.md). Редактор через `file://` подходит только для просмотра старого локального прототипа; сохранение проектов и шаблонов на сервере требует HTTP.

Один каталог `--data-dir` хранит `projects/*.json`, `templates/*.json`, `uploads/*` и `settings.json`. При первом успешном соединении старые шаблоны из `localStorage` **того же HTTP-адреса** переносятся в backend (при ошибке не удаляются). Шаблоны, созданные из `file://`, могут находиться в изолированном хранилище браузера и автоматически не переносятся. До 30 шаблонов на один backend, включая вложенные элементы.

Backend слушает только `127.0.0.1`; Python dev-сервер нужен лишь для локальной разработки и позже будет заменён nginx контроллера. Собственной авторизации нет; сетевой доступ предполагается только внутри доверенной локальной сети.

API: [docs/API.md](docs/API.md). Формат: [docs/PROJECT_FORMAT.md](docs/PROJECT_FORMAT.md). Подробности C++ backend: [backend/README.md](backend/README.md).

## MQTT-команды — шаг 12

В редакторе у кнопки, переключателя и ползунка появилась группа «MQTT · действие». Указывайте точный топик команды; у кнопки — отправляемое значение, у переключателя — значения ВКЛ/ВЫКЛ. Ползунок отправляет выбранное число при отпускании. MQTT подключается **только в отдельном просмотре**; backend не взаимодействует с брокером.

Работа с MQTT выполняется через WebSocket, QoS 0, retain=false. Доступность реального брокера и маршрута `/mqtt` на контроллере проверим в шагах 13–15. Описание: [docs/VIEWER.md](docs/VIEWER.md).
