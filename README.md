# WEBWB

WEBWB — лёгкий визуальный редактор панелей управления для контроллеров Wiren Board.

Пользователь собирает интерфейс из контейнеров, текста, кнопок, переключателей и ползунков, настраивает внешний вид и, в будущих версиях, привязывает элементы к MQTT-топикам. Правила и автоматизация остаются на самом контроллере.

Редактор поддерживает контейнеры, текст, кнопки, переключатели и ползунки, Drag & Drop, дерево, CSS, экспорт/импорт JSON, сохранение проектов на сервере и библиотеку шаблонов.
Добавление элементов — только перетаскиванием.

## Запуск и тесты — WSL

Нужны CMake, компилятор C++17, `libboost-dev`, `libjson-c-dev` и Python 3 (только для проверки/локального dev-сервера).

**Все автоматические тесты одной командой:**

```bash
cd /mnt/c/Projects/WEBWB
bash tests/check.sh
```

**Запуск редактора вместе с backend:**

```bash
cd /mnt/c/Projects/WEBWB
bash tests/run_editor.sh
```

Откройте в Windows **http://localhost:8090/**. Редактор через `file://` подходит только для просмотра старого локального прототипа; сохранение проектов и шаблонов на сервере требует HTTP.

Один каталог `--data-dir` хранит `projects/*.json` и `templates/*.json`. При первом успешном соединении старые шаблоны из `localStorage` **того же HTTP-адреса** переносятся в backend (при ошибке не удаляются). Шаблоны, созданные из `file://`, могут находиться в изолированном хранилище браузера и автоматически не переносятся. До 30 шаблонов на один backend, включая вложенные элементы.

Backend слушает только `127.0.0.1`; Python dev-сервер нужен лишь для локальной разработки и позже будет заменён nginx контроллера. Собственной авторизации нет; сетевой доступ предполагается только внутри доверенной локальной сети.

API: [docs/API.md](docs/API.md). Формат: [docs/PROJECT_FORMAT.md](docs/PROJECT_FORMAT.md). Подробности C++ backend: [backend/README.md](backend/README.md).

├── .gitignore                 # уже создан в репозитории

│   ├── styles.css
│   ├── app.js                # история, действия и обработчики событий

│       └── api.js           # HTTP-клиент проектов и шаблонов

│   ├── src/main.cpp          # HTTP-сервер
│   ├── src/project_validation.cpp # JSON-проверка
│   ├── src/project_store.cpp # хранение проектов
│   ├── src/template_store.cpp # хранение шаблонов
│   └── tests/
│       ├── project_validation_test.cpp
│       ├── project_store_test.cpp
│       └── template_store_test.cpp
├── tests/
│   ├── fixtures/project-v3.json
│   └── smoke_api.py            # автоматическая проверка API в WSL
└── docs/
    ├── ROADMAP.md
    ├── ARCHITECTURE.md
    ├── STATE.md
    ├── API.md
    ├── PROJECT_FORMAT.md
    ├── PROTOTYPE_V03.md
    └── assets/editor-v0.3.png

JavaScript разделён по ответственности без сборщика и ES-модулей: `model.js`, `view.js`, `properties.js`, `api.js`, `app.js` подключаются последовательно через `defer`. Проекты и шаблоны в рабочем HTTP-режиме хранятся на backend. Черновик проекта продолжает сохраняться локально для восстановления несохранённых правок. Для серверной работы используйте `tests/run_editor.sh`.
