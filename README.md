# WEBWB

WEBWB — лёгкий визуальный редактор панелей управления для контроллеров Wiren Board.

Пользователь собирает интерфейс из контейнеров, текста, кнопок, переключателей и ползунков, настраивает внешний вид и, в будущих версиях, привязывает элементы к MQTT-топикам. Правила и автоматизация остаются на самом контроллере.

## Текущее состояние

**Шаги 01–06 подтверждены**, последний коммит `db3fbaf94aabb0cea813d508954bea9d9550c8eb`. **Шаг 07 подготовлен и ожидает проверки владельца**: визуальный редактор подключён к C++ API для сохранения и открытия проектов. Нет MQTT, серверных шаблонов, настройки nginx и установки на контроллер.

Редактор поддерживает дерево контейнеров, текст, кнопки, переключатели, ползунки, CSS, Drag & Drop, шаблоны в браузере и импорт/экспорт JSON. Добавление из палитры — **только перетаскиванием**.

## Проверка — WSL (одна команда)

Нужны CMake >= 3.16, компилятор C++17, `libboost-dev`, `libjson-c-dev`, Python 3.

```bash
cd /mnt/c/Projects/WEBWB
bash tests/check.sh
```

Проверка выполняет полную сборку, 4 CTest, 12 проверок API C++ backend и 9 проверок доступа к редактору с API через общий адрес. Тестовые проекты размещаются **только во временном каталоге**.

## Запуск редактора с backend — WSL

```bash
cd /mnt/c/Projects/WEBWB
bash tests/run_editor.sh
```

В Windows откройте **http://localhost:8090/**. Оставьте WSL-терминал открытым; остановка — `Ctrl+C`.

Нажмите «Новый», введите название, добавьте компоненты, нажмите «Сохранить» — первый раз выполняется создание проекта на сервере (`POST`), следующие сохранения обновляют его (`PUT`). Выберите другой проект в списке и нажмите «Открыть с сервера» (`GET`). Кнопка ↻ обновляет список. Несохранённые изменения остаются локальным черновиком, но **не записываются на сервер автоматически**; перед потерей изменений появляется запрос подтверждения. Импорт из JSON создаёт новый черновик. Шаблоны пока сохраняются только в браузере.

Проекты из данного тестового режима сохраняются в `/tmp/webwb-dev-data/projects/` (путь WSL, отдельно от исходников). Если каталог удалён, проекты будут потеряны. Перед переносом на контроллер на этапе установки будет определено постоянное расположение `/mnt/data/webwb`.

`tests/dev_server.py` — только вспомогательный HTTP-сервер для WSL. Он запускает настоящий C++ backend и отдаёт HTML/CSS/JS с тем же origin, проксируя `/api`. На Wiren Board его заменит nginx; Python для production backend **не нужен**. При открытии HTML через `file://` серверные функции недоступны, но редактор может использовать локальный черновик и экспорт JSON.

Документация: [backend/README.md](backend/README.md), [docs/API.md](docs/API.md), [docs/PROJECT_FORMAT.md](docs/PROJECT_FORMAT.md).

## Структура

```text
WEBWB/
├── .gitattributes             # уже создан в репозитории
├── .gitignore                 # уже создан в репозитории
├── README.md
├── AGENTS.md                  # соглашения по работе над кодом
├── frontend/
│   ├── index.html
│   ├── styles.css
│   ├── app.js                # история, действия и обработчики событий
│   └── js/
│       ├── api.js           # HTTP-клиент к backend
│       ├── model.js         # данные проекта и JSON
│       ├── view.js          # дерево и отображение элементов
│       └── properties.js    # панель свойств и изменение CSS
├── CMakeLists.txt             # C++17 backend, CTest
├── backend/
│   ├── README.md             # требования и запуск в WSL
│   ├── include/webwb/project_validation.hpp
│   ├── include/webwb/project_store.hpp
│   ├── src/main.cpp          # HTTP-сервер
│   ├── src/project_validation.cpp # JSON-проверка
│   ├── src/project_store.cpp # файловое хранение
│   └── tests/
│       ├── project_validation_test.cpp
│       └── project_store_test.cpp
├── tests/
│   ├── fixtures/project-v3.json
│   ├── check.sh            # сборка, CTest, HTTP-проверки
│   ├── smoke_api.py        # тест API C++
│   ├── smoke_frontend.py   # тест dev server + API
│   ├── dev_server.py       # общий HTTP-адрес (только WSL)
│   └── run_editor.sh       # запуск редактора + C++ backend
└── docs/
    ├── ROADMAP.md
    ├── ARCHITECTURE.md
    ├── STATE.md
    ├── API.md
    ├── PROJECT_FORMAT.md
    ├── PROTOTYPE_V03.md
    └── assets/editor-v0.3.png
```

JavaScript без сборщика и без ES-модулей. Скрипты подключаются через `defer`: `model.js`, `view.js`, `properties.js`, `api.js`, `app.js`. Серверные функции работают по относительным HTTP-URL `/api/projects`. Сохранение выполняется вручную. Следующий этап после подтверждения шага 07 — серверная библиотека шаблонов (шаг 08).
