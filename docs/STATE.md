## Текущий шаг 07 — подключение редактора к API

В этом шаге:

- `frontend/js/api.js`: небольшой HTTP-клиент для `GET/POST/PUT /api/projects` и `GET /api/projects/:id`.
- `frontend/index.html`, `frontend/styles.css`: поле названия, список серверных проектов, кнопки «Открыть с сервера», «Сохранить», обновление списка, статус соединения.
- `frontend/app.js`: открытие выбранного проекта с сервера, сохранение через POST/PUT, новая пустая страница как черновик, отслеживание несохранённых изменений, защита от случайной замены черновика. Существующие экспорт/импорт JSON, Undo/Redo, Drag & Drop и шаблоны сохранены.
- `tests/dev_server.py` и `tests/run_editor.sh`: локальный режим разработки на одном HTTP-адресе (frontend + обратный прокси `/api` на C++ backend); Python только для WSL-проверок, не является production backend.
- `tests/smoke_frontend.py`: проверка работы общего адреса frontend/API. Она добавлена в `tests/check.sh` после CTest и прежнего smoke-теста.
- Документация: README, docs/ARCHITECTURE.md, docs/ROADMAP.md, docs/API.md, docs/STATE.md.

## Как проверить владельцу

1. Распаковать архив в `C:\Projects\WEBWB`.
2. В WSL выполнить `bash tests/check.sh`; ожидаются 4/4 CTest, прежние HTTP-проверки backend и 9 проверок общего адреса frontend/API.
3. Выполнить `bash tests/run_editor.sh`; открыть **http://localhost:8090/** в браузере Windows.
4. Нажать «Новый», задать название, добавить элемент, нажать «Сохранить». Изменить проект, снова сохранить; проверить открытие из списка, обновление страницы и восстановление проекта. Нажатие по палитре не должно добавлять элементы.
5. Завершить запуск через Ctrl+C, сделать git commit/push и прислать SHA, либо прислать ошибку.

## Ограничения

- Сервер хранит только проекты, а **шаблоны по-прежнему находятся в localStorage** (шаг 08).
- Несохранённые правки — черновик в localStorage; сохранение на сервер **явное** по кнопке. Восстановление связи и сохранение проекта после обновления страницы предусмотрены локальной привязкой к ID, но конфликтов одновременной правки разными клиентами backend пока не предотвращает (последняя запись побеждает).
- `file://` оставлен как офлайн-прототип, однако серверные кнопки там недоступны. Для работы с C++ API нужен HTTP и общий origin; в WSL это даёт `tests/run_editor.sh`, на Wiren Board позже — nginx (шаг 14).
- Свой backend слушает `127.0.0.1`, MQTT не подключён, авторизации приложения нет (только доверенная локальная сеть).
- Целевая сборка на Wiren Board, nginx/systemd и MQTT не проверялись.
