## Исправление проверки шага 06 — устаревший исполняемый файл

20.10.2026 владелец запустил `bash tests/check.sh`: прошли 4/4 CTest, `/api/health` и `/api/projects/validate`, но `POST /api/projects` возвращал HTTP 404 с `{"error":"not_found"}`. В журнале запущенного backend обнаружено `Data directory (not used yet)` — строка из backend **шага 05**, отсутствующая в актуальном `backend/src/main.cpp` шага 06 (в нём выводится `Projects directory: .../projects`). Следовательно, smoke-тест выполнялся на старом исполняемом файле, а не на новой реализации HTTP API.

Предполагаемая причина — переиспользование старых объектных файлов CMake из `/tmp/webwb-build` после распаковки ZIP на Windows: восстановленные архивом исходники могут иметь время изменения раньше уже собранных объектов. Это согласуется с симптомами; подтвердить точный механизм на WSL владельца пока нельзя.

**Исправление для проверки (архив `WEBWB-step-06-rebuild.zip`):**
- `tests/check.sh`: `cmake --build "$BUILD_DIR" --clean-first -j2` вместо инкрементальной сборки, затем обязательная проверка `webwb_backend --help` на поддержку маршрута проектов до запуска CTest/HTTP.
- `backend/src/main.cpp`: дополнительно включён актуальный исходник HTTP backend шага 06, чтобы восстановить его при частичной распаковке.
- `tests/smoke_api.py`: используется диагностическая версия, показывающая HTTP-статус и журнал при ошибке.
- `README.md`, `docs/STATE.md`: зафиксированы причина сбоя и способ проверки.

**Состояние:** ожидается повторная проверка в WSL и коммит владельца. C++-логика хранения, схема JSON и API **не изменены**. Шаг 07 ещё не начинался.

## Важные ограничения

- Редактор **ещё не подключён** к backend; его localStorage пока не изменён. Шаг 07 — подключение API.
- Backend использует `Boost.Beast` и `json-c`, без БД, работает на loopback, без своей авторизации, MQTT нет.
- Проекты пишутся атомарной заменой файлов на Linux; сервер пока последовательный и без механизма блокировок для нескольких процессов.
- Параметры сборки WB/toolchain пока не подтверждены (шаг 13).
- Git-команды: `git add .`, не предлагать `git diff --check`. Один шаг за цикл. Ассистент сам GitHub не меняет.
