## Текущий шаг

**03 — разделение frontend на небольшие модули**. Статус: **архив подготовлен, ожидается проверка и коммит владельца**.

### Изменения

- `frontend/js/model.js` — вынесены утилиты, описание компонентов и нормализация JSON.
- `frontend/js/view.js` — дерево, холст и список шаблонов.
- `frontend/js/properties.js` — настройки элементов и обработка изменений CSS.
- `frontend/app.js` — состояние приложения, история, Drag & Drop, копирование, шаблоны, события и запуск.
- `frontend/index.html` — последовательное подключение 4 файлов через `<script defer>`.
- `README.md`, `docs/ROADMAP.md`, `docs/ARCHITECTURE.md`, `docs/PROTOTYPE_V03.md`, `docs/STATE.md` — обновлена документация.
- `frontend/styles.css`, структура и версия JSON (`3`), localStorage, MQTT и внешний вид **не изменены**.

### Порядок загрузки

`js/model.js` → `js/view.js` → `js/properties.js` → `app.js`. Это классические JS-скрипты, так что `index.html` продолжает открываться через `file://` без сервера. Глобальные интеграционные точки: `WBPanelModel`, `WBPanelCreateView`, `WBPanelCreateProperties`. Остальной код заключён в IIFE.

## Проверено ассистентом

- `node --check` каждого нового/изменённого JS-файла: успешно.
- Автоматизированная проверка Chromium (загрузка HTML/CSS и последовательное выполнение JS): инициализация, клик по палитре без добавления, добавление через DnD, переключение скругления, режим просмотра, выгрузка JSON, изменение компоновки, Undo, копирование/вставка, шаблон и вставка через DnD, импорт JSON — успешно; ошибок JavaScript нет.
- В тестовой среде прямой переход к `file://` заблокирован политикой браузера (`ERR_BLOCKED_BY_ADMINISTRATOR`). **Открытие локальной страницы в браузере пользователя не проверено**.
- Сборка в WSL ещё не требуется, C++ backend не реализован.

## Проверить владельцу

1. Распаковать архив поверх репозитория (файлы в корневых относительных путях).
2. Открыть `frontend/index.html` с диска. Убедиться, что страница и дерево элементов загружаются без ошибок.
3. Добавить элементы перетаскиванием, изменить контейнер и скругление, переместить элемент в дереве.
4. Проверить копирование/вставку и вставку сохранённого шаблона.
5. Скачать JSON и снова открыть его в редакторе, проверить режим просмотра.
6. Commit/push, прислать новый SHA или ошибки.

## Правила

- Один шаг за цикл; без новых возможностей редактора в шаге 03.
- Git: `git add .`, **не выдавать** `git diff --check`.
- Frontend: HTML/CSS/Vanilla JS без сборщика; backend далее на C++17/CMake в WSL, хранение JSON/файлы, MQTT только в режиме просмотра, отдельной авторизации нет.
