## Текущий шаг

**04 — каркас C++ backend.** Статус: **изменения подготовлены в архиве; локальная проверка владельца и коммит ещё не подтверждены**.

### Изменения

- `CMakeLists.txt`: сборка исполняемого файла `webwb_backend`, C++17, Boost.Beast/Asio (заголовки), Threads, два CTest теста.
- `backend/src/main.cpp`: минимальный локальный HTTP-сервер (только `127.0.0.1`), `GET /api/health`, ответы `404`/`405`, журнал запуска и ошибок.
- Аргументы: `--port` (по умолчанию `8088`), `--data-dir` (по умолчанию `/mnt/data/webwb`) и `--help`. Путь данных пока **только параметр**, файловые операции не выполняются.
- `backend/README.md`, `README.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, `docs/STATE.md`: обновлена документация.
- `frontend/` в этом шаге **не изменялся**.

### Архитектурные решения

- HTTP библиотека: **Boost.Beast** (без собственного HTTP-парсера). В WSL для сборки нужен пакет заголовков `libboost-dev`; CMake ничего не скачивает.
- Перед целевой сборкой под Wiren Board проверить версию компилятора и наличие заголовков Boost для нужной архитектуры; это пока **не подтверждено**.
- Хранилище: JSON на диске, без СУБД (реализация далее); backend не участвует в MQTT.
- Собственной авторизации нет, API не публиковать напрямую в Интернет. Сервер слушает loopback-интерфейс.
- На шаге 04 обработка соединений синхронная, одно за раз; HTTP-чтение ограничено 5 секундами, 16 KiB заголовков и 1 MiB тела.

## Что проверено ассистентом

- Конфигурация CMake, компиляция `webwb_backend` GCC 14.2 (Linux): **успешно**.
- `ctest`: 2/2 успешно (`--help`, запрет порта `0`).
- Реальные HTTP-запросы: `GET /api/health` → `200` с JSON; неизвестный путь → `404`; `POST /api/health` → `405` с `Allow: GET`.
- Проверено, что сокет слушает только `127.0.0.1`.
- **WSL пользователя и целевой Wiren Board не тестировались**.

## Проверить владельцу

1. Распаковать архив поверх рабочей копии на `f7929ad...`.
2. Выполнить сборку и CTest из `backend/README.md` в WSL.
3. Запустить backend; из другого терминала WSL сделать `curl -i http://127.0.0.1:8088/api/health`.
4. Убедиться, что возвращается `200 OK` и JSON `{"status":"ok","service":"webwb"}`.
5. Остановить backend `Ctrl+C`, убедиться, что редактор `frontend/index.html` работает как прежде.
6. После успешной проверки сделать commit/push и прислать SHA или сообщение об ошибке.

## Ограничения

- Пока нет API проектов/шаблонов, JSON-валидации, MQTT, nginx/systemd, установки на WB.
- Каталог данных пока не создаётся; `--data-dir` не используется для записи.
- При тестах из браузера другой машины loopback backend недоступен — это задумано, доступ через nginx будет добавлен позднее.
- По Git использовать `git add .`, **не выдавать** `git diff --check`.
