# WEBWB — отдельная страница просмотра (шаги 10–12)

## Назначение

Показывает последнюю **сохранённую на backend** версию интерфейса без палитры, дерева, панели CSS и кнопок редактора. Работает на том же HTTP-адресе, что и API. Начиная с шага 11, элементы читают MQTT-состояния, а начиная с шага 12 — отправляют MQTT-команды по действиям пользователя. Элементы без топиков остаются демонстрационными.

## Запуск в WSL

```bash
cd /mnt/c/Projects/WEBWB
bash tests/run_editor.sh
```

Откройте в браузере Windows `http://localhost:8090/`, сохраните проект и нажмите **Открыть панель**. В новой вкладке загрузится `http://localhost:8090/viewer.html?id=<ID проекта>`.

Ссылка появляется **только после сохранения проекта**. Несохранённые правки редактора в отдельном viewer не появляются до следующего сохранения; затем вкладку viewer нужно обновить. Отсутствующий/неверный/удалённый ID выводит понятное сообщение.

## Устройство

- `frontend/viewer.html` — минимальная HTML-страница.
- `frontend/viewer.js` — чтение ID, запрос проекта через HTTP API, обновление DOM по состояниям MQTT.
- `frontend/js/mqtt_reader.js` — подписка и публикация команд через MQTT WebSocket.
- `frontend/js/renderer.js` — общая DOM-отрисовка с редактором.
- `frontend/viewer.css` — оформление страницы просмотра; стили компонентов общие (`frontend/styles.css`).
- `tests/dev_server.py` — HTTP для WSL; в production заменяется nginx.

Открытие через `file://` для viewer не поддерживается — нужен общий HTTP-origin с backend. HTML на сервере не генерируется, браузер создаёт DOM по JSON.

## Проверка

`bash tests/check.sh` проверяет C++ backend, API и выдачу файлов viewer. Визуальную работу и отображение сохранённого проекта нужно проверить в браузере.

## MQTT-состояния — шаг 11

В редакторе выделите элемент «Текст», «Кнопка», «Переключатель» или «Ползунок», откройте **MQTT · состояние** и задайте полный топик. Для кнопки/переключателя задайте значение активного состояния, обычно `1`. Сохраните проект, затем откройте панель заново.

- Текст: показывает подпись и последнее полученное значение (если подпись пустая — только значение).
- Кнопка: подсвечивается, когда значение сообщения точно совпало с активным.
- Переключатель: визуально следует за значением сообщения, в шаге 12 может отправлять команды при действии.
- Ползунок: показывает принятое числовое значение, в шаге 12 отправляет значение после отпускания, если задан топик команды.

По умолчанию подключение идёт на `ws(s)://<хост страницы>/mqtt` — это путь для размещения за совместимым nginx. Для прямого доступа к WebSocket-порту брокера в ссылке можно указать `&mqttUrl=ws://IP_КОНТРОЛЛЕРА:18883/` (адрес и порт зависят от конфигурации WB). **WSL dev-сервер не содержит MQTT-брокер и не проксирует `/mqtt`**. В HTTPS-странице нужен `wss://` или серверный HTTPS WebSocket-прокси.

Панель показывает состояние подключения; при обрыве соединение восстанавливается автоматически. Клиент подписывается на точные топики с QoS 0 и получает сохранённые брокером retained-значения, если они есть. До первого сообщения остаются значения по умолчанию. Тест без брокера: `bash tests/check.sh` (MQTT-проверка выполняется при наличии Node.js).

## MQTT-команды — шаг 12

В редакторе выберите **кнопку**, **переключатель** или **ползунок**, затем задайте **MQTT · действие → Топик команды**. Открывать соединение в редакторе не требуется — MQTT используется только в отдельном просмотре.

- Кнопка: отправляет нажатие в `actionTopic`, значение `actionValue` (по умолчанию `1`).
- Переключатель: отправляет `onValue` или `offValue` (по умолчанию `1`/`0`) в один `actionTopic`.
- Ползунок: отправляет выбранное число в `actionTopic` **только после завершения перемещения**.
- Можно назначить только команду, только статус или оба топика. Если задан статус, отображаемое фактическое состояние обновляется по сообщениям брокера.

MQTT-команды отправляются QoS 0, retain=false. Когда нет соединения, команда не отправляется, страница показывает уведомление. Клиент может переподключаться. Успешная запись в WebSocket **не гарантирует**, что устройство выполнило команду — наблюдайте за фактическим `statusTopic`.

Для тестов без настоящего брокера выполните `bash tests/check.sh` — Node.js симулирует WebSocket, CONNECT, CONNACK, публикацию и отключение. Работа на реальном контроллере проверяется на этапах 13–15. Автоматизация остаётся в правилах Wiren Board.
