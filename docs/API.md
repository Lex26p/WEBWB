# WEBWB — API проектов (шаг 06)

Состояние: реализовано на C++ backend, **не подключено к редактору**. Действует JSON версии 3 из [PROJECT_FORMAT.md](PROJECT_FORMAT.md).

Базовый адрес при запуске в WSL: `http://127.0.0.1:8088`. Сервис слушает только loopback. Авторизации приложения нет; API не предназначен для доступа из Интернета.

## Проекты

| Метод и путь | Успех | Что возвращает |
|---|---|---|
| `GET /api/projects` | `200` | `{"projects":[{"id":"...","title":"..."}]}` |
| `POST /api/projects` | `201` | `{"id":"..."}`, заголовок `Location: /api/projects/<id>` |
| `GET /api/projects/<id>` | `200` | Исходный JSON проекта версии 3 |
| `PUT /api/projects/<id>` | `200` | `{"updated":true}` |
| `DELETE /api/projects/<id>` | `204` | Пустое тело |

`POST` и `PUT` принимают **тело JSON-проекта**, не обёрнутое в отдельное поле. Новый проект получает сгенерированный сервером идентификатор из 32 шестнадцатеричных символов. Этот ID относится к файлу хранения, а не к `root.id` внутри проекта. `PUT` заменяет содержимое существующего проекта, не меняя его ID. Порядок списка определяется ID.

### Ответы при ошибках

- `400` `{"error":"invalid_project","detail":"..."}` — неверный JSON или данные, не соответствующие схеме.
- `404` `{"error":"not_found"}` — отсутствующий проект или неверный идентификатор.
- `405` `{"error":"method_not_allowed"}` + `Allow` — метод не поддерживается.
- `500` `{"error":"storage_error"}` — проблема чтения, записи или повреждение сохранённого проекта; подробности только в stderr сервера.
- Тело HTTP ограничено 1 МиБ, размер заголовков 16 КиБ, чтение запроса — 5 секунд. Нарушения этих ограничений обрабатываются на уровне Boost.Beast; полноценная JSON-ошибка не гарантирована.

Сохранились диагностические маршруты:

- `GET /api/health` — `200 {"status":"ok","service":"webwb"}`.
- `POST /api/projects/validate` — проверка JSON без сохранения (`200` / `400`).

## Файловое хранение

При запуске с `--data-dir /tmp/webwb-data` сервер создаёт `/tmp/webwb-data/projects/`.

Каждый проект хранится по пути `projects/<id>.json`. Данные записываются во временный файл в том же каталоге, синхронизируются, затем заменяются через `rename`; повреждённый документ не должен попадать на диск через API. Список формируется из файлов проектов. Временные и посторонние файлы игнорируются.

При ошибке чтения одного из сохранённых документов запрос списка отвечает `500`, а не скрывает ошибку. Сервер не делает резервные копии: их организация — отдельная задача эксплуатации.

### Пример проверки из WSL

```bash
curl -i -X POST -H 'Content-Type: application/json' --data-binary @tests/fixtures/project-v3.json http://127.0.0.1:8088/api/projects
curl -i http://127.0.0.1:8088/api/projects
```

Возьми `id` из ответа POST для остальных маршрутов. Пример: `curl -i http://127.0.0.1:8088/api/projects/<id>` (замени `<id>` на реальное значение).

## Ограничения

- HTTP-сервер сейчас однопоточный, запросы выполняются последовательно; параллельную нагрузку и изменения внешними процессами пока не поддерживаем.
- В режиме редактора по-прежнему используется `localStorage`. Подключение браузера к API — **шаг 07**.
- Нет MQTT, шаблонов и изображений в backend, nginx и systemd — будущие шаги.


## Серверная библиотека шаблонов — шаг 08

| Метод и путь | Результат | Ответ |
|---|---|---|
| `GET /api/templates` | `200` | `{"templates":[{"id":"...","name":"...","node":{...}}]}` |
| `POST /api/templates` | `201` | `{"id":"..."}`, также заголовок `Location: /api/templates/<id>` |
| `DELETE /api/templates/<id>` | `204` | Пустое тело |

Для создания передаётся полный JSON-документ `{ "name": "Свет", "node": { ... } }`.
`node` — исходное дерево элемента из редактора, с поддержкой контейнеров и вложенности, по тем же правилам, что и в JSON-проекте версии 3.
Значение `id` для API присваивается сервером и не должно присутствовать в POST-теле. В JSON-файле храним `name` и `node`, а ID берём из имени файла.

Шаблоны хранятся в `<data-dir>/templates/<id>.json`; до 30 шаблонов на сервер. Имя до 80 символов UTF-8. Лимит JSON-документа 1 МиБ, проверка вложенности/типов/стилей такая же, как для проекта.

Ошибки: `400 invalid_template`, `404 not_found`, `405 method_not_allowed`, `409 template_limit`, `500 storage_error`.
Удаление необратимо; для первой версии восстановления удалённого шаблона нет.
Старая локальная библиотека из `localStorage` того же HTTP-origin автоматически переносится при первом успешном подключении редактора к backend; совпадающие шаблоны не дублируются. При сбое переноса локальные копии сохраняются до успешной попытки. Старый `file://`-origin может быть изолирован от `http://localhost:8090/` и не будет автоматически доступен для переноса.

## Изображения и настройки — шаг 09

| Запрос | Успех | Ответ |
|---|---|---|
| `GET /api/uploads` | 200 | `{"uploads":[{"id":"...","mime":"image/png","size":123}]}` |
| `POST /api/uploads` | 201 | `{"id":"...","url":"/api/uploads/..."}` |
| `GET /api/uploads/<id>` | 200 | Бинарный файл PNG/JPEG/WebP, корректный MIME |
| `DELETE /api/uploads/<id>` | 204 | Пустое тело |
| `GET /api/settings` | 200 | `{"title":"WEBWB"}` (или сохранённое значение) |
| `PUT /api/settings` | 200 | `{"updated":true}` |

Для `POST /api/uploads` передавать содержимое файла как бинарное тело HTTP (не JSON и не multipart). Допускаются PNG, JPEG, WebP до 1 МиБ. MIME определяется сервером по сигнатуре; SVG не принимается. Ошибки: `400 invalid_image`, `404 not_found`, `405 method_not_allowed`, `500 storage_error`; превышение HTTP body limit может быть отклонено на уровне сервера.

Сервер присваивает идентификатор изображения сам. `GET` возвращает `X-Content-Type-Options: nosniff`. Список не содержит оригинальные имена файлов; повторная загрузка создаёт новый ресурс. Удаление изображения не меняет проекты и шаблоны с его URL.

Настройки — отдельный маленький JSON-файл в `<data-dir>/settings.json`, пока единственное поле `title` (непустая строка до 120 байт). `PUT` требует именно объект `{"title":"..."}`; дополнительные поля и неверные типы отвергаются (`400 invalid_settings`). Запись выполняется через временный файл и переименование. При отсутствии файла GET отдаёт значение по умолчанию без создания файла.
