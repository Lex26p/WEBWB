# WEBWB — дорожная карта разработки

Версия плана: 1.0 · 19 октября 2026 г.

## Цель

Лёгкий локальный конструктор панелей управления для Wiren Board. Пользователь собирает интерфейс из контейнеров и простых элементов, настраивает свойства, сохраняет проект на контроллере. В режиме просмотра элементы отображают MQTT-состояния и отправляют команды. Логика автоматизации остаётся в Wiren Board.

## Зафиксированные решения

- Frontend: HTML, CSS, JavaScript без фреймворков; добавление из палитры — только перетаскиванием.
- Backend: C++ (целевой стандарт C++17, если позволит имеющийся toolchain), CMake, небольшой HTTP API.
- Backend **не** исполняет автоматизацию и **не** подключается к MQTT.
- Данные: JSON-файлы проектов, шаблонов и настроек; изображения хранятся как файлы. Без СУБД на первом этапе.
- MQTT: WebSocket в браузере **только при просмотре**; MQTT-настройки задаются в редакторе.
- Развёртывание: на Wiren Board. Отдача фронтенда и проксирование API — через существующий веб-сервер контроллера, после проверки конкретного окружения. Backend запускается как сервис.
- Собственная авторизация приложения не реализуется по решению владельца проекта. Приложение рассчитано на доверенную локальную сеть, без публикации в Интернет. Тем не менее backend проверяет входящие данные, пути и размеры файлов; API-процесс слушает localhost.
- Репозиторий и подтверждённый commit hash — источник истины. За один цикл выполняется **только один шаг**.

## Предварительная структура репозитория

```text
WEBWB/
  README.md
  .gitignore
  CMakeLists.txt               # backend C++17 + Boost.Beast + json-c
  frontend/
    index.html                 # редактор
    viewer.html                # появится на шаге 10
    styles.css
    app.js
    js/
      model.js
      view.js
      properties.js
  backend/
    README.md
    include/webwb/project_validation.hpp
    src/main.cpp
    src/project_validation.cpp
    tests/project_validation_test.cpp
  docs/
    ROADMAP.md
    ARCHITECTURE.md
    STATE.md
  tests/fixtures/project-v3.json
```

**На контроллере**, отдельно от файлов программы:

```text
/mnt/data/webwb/
  projects/
  templates/
  uploads/
  settings.json
```

Фактический путь хранения и интеграция с nginx подтверждаются на целевой прошивке перед установкой.

## Правила одного цикла разработки

1. Ассистент кратко объясняет **один** очередной шаг и критерий готовности.
2. Читает текущие релевантные файлы **из репозитория**, сверяет коммит и документацию. Не заменяет репозиторий предположениями о предыдущих версиях.
3. Изменяет реальные файлы проекта, обновляет документацию и создаёт **ZIP с готовыми файлами по относительным путям от корня репозитория**. Никаких скриптов, которые вместо архива создают исходники.
4. Даёт **один простой PowerShell-блок** для распаковки из `C:\Users\pereverworkki\Downloads` в `C:\Projects\WEBWB` с сохранением структуры папок.
5. По возможности предоставляет **готовый проверочный скрипт в `tests/`**, запускаемый одной WSL-командой, без ручного набора нескольких `curl`-запросов. Даёт команды сборки/проверки и только необходимую ручную проверку.
6. Даёт **один WSL-блок Git-команд**: проверить статус, добавить нужные файлы, commit, push, показать commit hash.
7. Владелец присылает хеш коммита или ошибки. Пока шаг не подтверждён, следующий не начинаем.

Команды должны оставаться простыми и быть сгруппированы по назначению. Не включать в архив сгенерированные `build/`, временные файлы и бинарники. Команды сборки зависят от фактически согласованной среды.

## Документация между чатами

- `docs/ROADMAP.md`: согласованная последовательность и статус шагов.
- `docs/ARCHITECTURE.md`: архитектура, формат хранения, API, важные решения.
- `docs/STATE.md`: текущий шаг, последний подтверждённый коммит, сделанные изменения, что проверено, известные проблемы, следующий шаг.
- `README.md`: быстрый запуск и сборка.

При переходе в новый чат владелец присылает URL репозитория и последний commit hash. Ассистент читает документацию и код этого коммита, а не полагается на историю переписки.

## Что уточнить до этапа внедрения

- Модель(и) Wiren Board и версия прошивки.
- Имеющийся в WSL компилятор/архитектура целевой сборки.
- Доступные сервер, WebSocket MQTT и схемы маршрутизации на целевой прошивке.
- Совместимость Boost.Beast (HTTP) и будущей JSON-библиотеки с toolchain, особенно при целевой сборке под WB. HTTP-библиотека определена на шаге 04; вариант сборки под контроллер ещё не проверен.

Проектная JSON-схема шага 05 документирована отдельно в `docs/PROJECT_FORMAT.md`; пока нет записи на диск.
