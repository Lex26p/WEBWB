## Пример

```json
{
  "version": 3,
  "title": "Моя панель",
  "root": {
    "id": "page",
    "type": "container",
    "name": "Страница",
    "style": { "width": "100%", "backgroundColor": "#ffffff" },
    "children": [
      {
        "id": "el_light",
        "type": "button",
        "name": "Кнопка света",
        "style": { "borderRadius": "12px" },
        "text": "Свет"
      }
    ]
  }
}
```

Полный пример, сгенерированный существующей моделью редактора: `tests/fixtures/project-v3.json`.

## Ограничения текущего валидатора

- Размер исходного документа — до **1 МиБ** (1 048 576 байт).
- Корень JSON — объект с `version: 3`, строкой `title` (до 120 символов) и объектом `root`.
- `root.type` строго равен `container`.
- Поддерживаемые типы узлов: `container`, `text`, `button`, `switch`, `slider`, `image`.
- Каждый узел содержит `id`, `type`, `name` и `style`.
- `id` — уникальная внутри проекта строка из 1–80 символов `[A-Za-z0-9_-]`.
- `name` — строка до 150 символов; `style` — объект со свойствами из списка `STYLE_KEYS` модели JS. Значения стилей — строки до 120 символов.
- Контейнер обязательно содержит массив `children`; у других типов его быть не должно.
- Текст, кнопка и ползунок содержат строковое поле `text` (до 10 000 символов).
- Переключатель содержит `checked` типа `boolean`.
- Изображение (`type: image`) содержит `src` — пустую строку или строго локальный URL `/api/uploads/<32 шестнадцатеричных символа>`. Пользовательские URL и `javascript:` не допускаются. Никакой встроенной подписи нет.
- Ползунок содержит числовые `min`, `max`, `step`, `value`: `min` в диапазоне -10000…10000, `max` не менее `min + 1` и не более 10001, `step` в диапазоне 1…10000, `value` в пределах `[min, max]`.
- Не более **400 элементов**, корневой элемент считается первым. Вложенность до **20 уровней ниже корня**.

При проверке используются JSON-типы, а не преобразование всех значений в строки. Лишние поля объекта не интерпретируются валидатором, но неизвестные свойства внутри `style` отклоняются. При несовместимых изменениях повышаем версию формата; необязательные MQTT-поля шагов 11–12 совместимы с JSON v3.

### Совместимость

`frontend/js/model.js` уже умеет импортировать старые проекты v1/v2 и приводить их к формату 3. Backend **не мигрирует** старые форматы: открыть такой проект в редакторе и заново экспортировать JSON версии 3.

Схема не превращает JSON в HTML и не выполняет переданные стили. Начиная с шага 06 backend **проверяет JSON перед записью** на диск.

## Проверочный API (шаг 05)

```text
POST /api/projects/validate
Content-Type: application/json
<тело — проект JSON>
```

- `200 {"valid":true,"version":3}` — проект соответствует формату.
- `400 {"valid":false,"error":"invalid_project","detail":"..."}` — JSON некорректен или схема нарушена.
- `405` — другой HTTP-метод.

Этот маршрут нужен для проверки при разработке; это **не** создание проекта и не постоянное хранилище.

## Сохранение (шаг 06)

JSON версии 3 сохраняется в `<data-dir>/projects/<id>.json`; операции CRUD описаны в [API.md](API.md). ID генерируется сервером, не зависит от имени файла, заголовка или ID корневого контейнера. Файлы проверяются при чтении, а обновление выполняется через временный файл и переименование. Редактор подключится к серверному API отдельно на шаге 07.


## MQTT-поля (шаги 11–12)

MQTT-привязка необязательна и доступна только `text`, `button`, `switch`, `slider`. Формат проекта остаётся **v3**. В `mqtt` должен присутствовать хотя бы один топик — `statusTopic` или `actionTopic`.

- `statusTopic` — топик для получения значения; у `text`, `button`, `switch`, `slider`.
- `activeValue` — строка до 120 символов, только для статуса `button`/`switch`, по умолчанию `"1"`.
- `actionTopic` — топик для отправки команды, только для `button`, `switch`, `slider`.
- `actionValue` — значение при нажатии `button`, по умолчанию `"1"`.
- `onValue` / `offValue` — значения для включения/выключения `switch`, по умолчанию `"1"` и `"0"`.
- `slider` отправляет текущую числовую величину строкой **по завершении изменения** (`change`), отдельных полей значения нет.

Топики — непустые строки до **256 байт UTF-8**, без MQTT-масок `+` и `#`. Значения команд — строки до 120 символов; unknown MQTT-поля отвергаются сервером. У `text` нет команд, у контейнера и изображения вообще нет MQTT-привязок.

Пример кнопки со статусом и действием:

```json
"mqtt": {
  "statusTopic": "/devices/demo/controls/Relay",
  "activeValue": "1",
  "actionTopic": "/devices/demo/controls/Relay/on",
  "actionValue": "1"
}
```

Пример переключателя только с действием:

```json
"mqtt": {
  "actionTopic": "/devices/demo/controls/Relay/on",
  "onValue": "1",
  "offValue": "0"
}
```

Старые проекты без `mqtt` и проекты с одним `statusTopic` совместимы. Backend лишь проверяет и сохраняет эту конфигурацию; MQTT-сообщения публикуются **только браузером в режиме просмотра**. Используется MQTT 3.1.1, QoS 0, retain=false. Подтверждения доставки брокером при QoS 0 нет.
